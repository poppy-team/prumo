# Objetivo

Tratar o editor como engine própria do cliente, sem transformar o Prumo Core em text editor. O design deve suportar revisão rápida desde cedo e crescer até editing sofisticado sem reescrita estrutural.

# Referências

- **Helix:** rope, transactions/undo, multi-selection, LSP, DAP, Tree-sitter, terminal UI;
- **Lapce:** Rust native editor architecture, Floem, rope/editor primitives e LSP;
- **Zed:** GPU editor, collaboration e GPUI;
- **Oride:** nossa referência prática de mini-IDE TUI modular já implementada.

# Editor model

```
Document
├── immutable/revision identity
├── rope/text buffer
├── selections/cursors
├── transaction history
├── diagnostics
├── syntax layers
├── dirty/external change state
└── file encoding/EOL
```

# Transaction-first editing

Agent patches, user edits, LSP code actions e undo/redo devem convergir para uma operação transacional rastreável. Isso facilita diff, conflict detection e replay.

# Large files

Planejar desde o início:

- lazy/streaming open;
- viewport-only syntax/render;
- bounded diagnostics;
- incremental search;
- file size capability fallback;
- binary detection;
- avoid whole-document copies.

# Syntax

Tree-sitter é bom candidato para incremental highlighting e structural queries. Não deve ser obrigatório para abrir um arquivo.

# LSP

On-demand lifecycle por workspace/language. Compartilhar language intelligence com o Harness onde fizer sentido, evitando spawn duplicado de servidores entre client e agent.

# DAP

Debug Adapter Protocol é P1/P2 do editor, não bloqueador do primeiro coding cockpit.

# Search

Para fuzzy matching Rust, estudar **Nucleo**, usado no ecossistema Helix. Para grep, preferir engine/CLI altamente otimizada por provider e output estruturado em vez de implementar regex scanner ingênuo.

# Agent-aware editing

- mostrar patches proposed/applied;
- link diff a tool call/evidence;
- conflitos entre edit do usuário e agent;
- lock/lease apenas onde necessário;
- ability to accept/reject hunks sem perder trajectory.
