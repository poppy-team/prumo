> Status: Especificação especializada do Harness / Code Agent (Capítulo 20).


# Propósito

Separar **ideias de produto valiosas** das escolhas arquiteturais que não queremos necessariamente herdar.

| Dimensão | Panes | Paseo | Oride | Prumo Code Direction |
| --- | --- | --- | --- | --- |
| Papel | desktop cockpit | multi-client agent orchestration | TUI mini-IDE | harness + clients |
| Core stack | Rust/Tauri + web frontend | TypeScript daemon + Electron/Expo | Rust native TUI | Go Harness; native clients |
| Desktop UI | React/CodeMirror/xterm.js | Electron/web | n/a | native GPU/software-rendered candidate |
| Terminal | xterm.js/WebGL + PTY | agent/daemon surfaces | embedded PTY | native VT core + PTY |
| Editor | CodeMirror | client-dependent | rope editor | native editor engine |
| Multi-agent | multi-launch/harness | central feature | não é foco | Run/subagent first-class |
| Remote | local-first | forte: daemon/cross-device | SSH/TUI naturalmente | local first; remote depois |
| Performance identity | Tauri reduz Electron, mas UI web permanece | produto amplo, stack pesada | budgets agressivos | performance contract |

# Panes — ideias para absorver

- structured streaming blocks;
- diff/approvals;
- Git/worktree UX;
- terminal groups/splits;
- command palette;
- session recovery;
- harness detection/launch;
- multi-repo cockpit.

# Panes — escolhas a reavaliar

React/CodeMirror/xterm.js são excelentes ferramentas, mas conflitam com nossa meta explícita de reduzir browser/WebView overhead. Tauri por si só não torna o presentation stack nativo.

# Paseo — ideias para absorver

- daemon/client architecture;
- multi-provider agents;
- headless CLI equivalente ao app;
- remote attach;
- cross-device como capability separada;
- plugin/provider architecture;
- handoff/advisor/committee patterns.

# Paseo — escolhas a reavaliar

Electron + Expo + grande monorepo TypeScript entrega portabilidade e velocidade de produto, mas não é nossa direção se performance em hardware modesto for requisito primário.

# Oride — ideias para absorver e superar

- crates/boundaries claras;
- rope editor;
- Ratatui;
- PTY;
- Git;
- Tree-sitter;
- on-demand LSP;
- splits/mouse;
- explicit startup/input/binary budgets.

# Evolução além do Oride

O Prumo Code TUI pode adicionar aquilo que Oride não foi desenhado para centralizar: Agent Runtime, Goals/Runs, ACI, permissions, Evidence/Gates, sandbox/worktrees, trajectory e remote attach.
