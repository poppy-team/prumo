# Permission Engine v2

A decisão não deve ser apenas `tool allowed`. O pedido deve carregar contexto suficiente para policy avaliar intenção e recurso.

```
PermissionRequest
  agent / role
  action
  resource / target
  arguments summary
  filesystem scope
  network destinations
  credential scopes
  data class
  reversibility
  risk
  run / turn
```

Resultado:

```
allow | ask | deny
scope: once | turn | session | run | project
reason
constraints
expiry
```

# Path containment

O runtime atual deve deixar de usar prefix matching textual como garantia de containment. A versão de harness precisa considerar canonicalização, `Clean/Abs`, volumes/drives, symlinks/junctions, `..`, race/TOCTOU e regras do filesystem da plataforma.

# Worktree não é sandbox

Git worktree isola branch/workspace de Git; não isola processo, kernel, filesystem global, IPC, credentials ou network.

# SandboxProvider

```
SandboxProvider
├── LocalTrusted
├── Worktree
├── Container: Docker/Podman
├── Strong Linux: gVisor
├── Remote: E2B/Daytona/other adapters
└── microVM: Firecracker - futuro
```

# Estratégia por risco

| Perfil | Ambiente | Uso |
| --- | --- | --- |
| trusted-local | host + project root | usuário explicitamente confia no agent |
| isolated-worktree | worktree | concorrência Git, não security boundary |
| container | container rootless quando possível | coding agent padrão |
| restricted | gVisor/microVM/remote strong sandbox | untrusted code ou ferramentas agressivas |

# Egress

Network deve ser capability explícita, com destination policy. Dados `restricted` não saem; `confidential` exige destino aprovado e transporte seguro. Tool call com credencial deve carregar credential scope e destination.

# Secrets

O modelo não deve receber segredo quando apenas o tool/provider precisa dele. Preferir secret references resolvidas no boundary de execução.

# Resource limits

CPU, RAM, process count, file size, disk, network bytes, timeout e PTY lifetime devem integrar Environment/Budget.

# Aprovação

Approval é evento persistido e auditável. Não é apenas modal na UI. Qualquer client capaz de aprovar precisa enviar uma decisão vinculada ao PermissionRequest e à policy vigente.

# Futuros experimentos

- macOS sandbox primitives;
