# Agent Computer Interface

O coding agent não deve enxergar o computador apenas como `bash`. Inspirado pela ideia de ACI do SWE-agent, o Prumo deve fornecer ferramentas estruturadas, com output curto, schemas previsíveis e feedback imediato.

# ACI nativa candidata

| Grupo | Tools | Objetivo |
| --- | --- | --- |
| Filesystem | `fs.read`, `fs.list`, `fs.search`, `fs.stat` | leitura bounded e estruturada |
| Code | `code.symbols`, `definition`, `references`, `diagnostics` | inteligência sem grep massivo |
| Edit | `edit.patch`, `edit.replace`, `edit.create` | mudanças verificáveis |
| Git | `git.status`, `diff`, `log`, `stage` | SCM estruturado |
| Quality | `test.run`, `build.run`, `lint.run` | evidence |
| Process | `process.exec`, `process.pty` | execução controlada |
| Agent | `agent.delegate`, `agent.ask` | subagents/consultoria |
| Artifacts | `artifact.read`, `artifact.search` | outputs grandes fora do contexto |

# Protocolo das boundaries

## MCP — Agent ↔ Tool

Usar o SDK oficial Go quando apropriado, atrás do Tool Gateway. Servidores MCP permanecem untrusted-by-default e não recebem autoridade canônica.

## ACP — Client/Editor ↔ Agent

ACP é **first-class e bidirecional no produto**, em dois papéis distintos:

- **ACP Client:** Prumo consome coding agents externos compatíveis;
- **ACP Agent Server:** Prumo expõe seu próprio Agent Runtime a editores e clientes externos.

Mapear session/new/resume/prompt/update/permission/cancel para Run/ExecutorSession/Turn/Permission/Events. O ACP Registry pode ser usado para descoberta e metadata de instalação/auth, sempre sujeito a trust e permission gates.

ACP não é método de autenticação de modelo. O agente conectado pode anunciar ou executar seu próprio OAuth/device flow/terminal auth. Quando um runtime oficial possui as credenciais, o Prumo não deve extrair/copiar seus tokens.

## A2A — Agent ↔ Agent

Futuro. Útil apenas quando houver agentes independentes/remotos que não sejam meros subagents internos do mesmo runtime.

# Regra

```
ACP = Client/Editor ↔ Agent
MCP = Agent ↔ Tool/Context
A2A = Agent ↔ Agent remoto/independente

MCP != ACP != A2A
```

A arquitetura detalhada de runtimes externos, OAuth vendor-managed, SDK/RPC/CLI e providers customizados está em [22 — Agent Connectivity Runtime: Providers, OAuth, ACP, SDK, RPC e CLI](ch22.md).

Não usar um protocolo como substituto conceitual dos outros.

# Tool result design

Tool output deve ser bounded, resumível e apontável por artifact/hash. Para comandos sem output, retornar explicitamente sucesso/exit code para evitar ambiguidade ao modelo.

# Edição

Patch deve validar base revision ou content hash para evitar aplicar mudança sobre arquivo que mudou silenciosamente.

# Tool discovery

Resumo/capabilities primeiro; schema completo somente quando a tool se tornar candidata ao turno atual.
