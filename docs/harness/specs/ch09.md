# Objetivo

Criar um **cockpit nativo para coding agents**, não necessariamente uma IDE generalista. Panes e Paseo são referências de produto; nossa oportunidade é redesenhar a arquitetura para desempenho, modularidade e integração profunda com o Harness.

# O que Panes demonstra

Panes reúne streaming chat, Codex/Claude/OpenCode, Git, worktrees, editor multi-tab, command palette e PTY. Sua shell é Tauri/Rust, mas a apresentação usa React/TypeScript, CodeMirror e xterm.js/WebGL. Isso reduz parte do custo de Electron, porém ainda mantém um frontend web e sua cadeia de dependências.

# O que Paseo demonstra

Paseo coloca um daemon no centro e oferece desktop, mobile, web e CLI; gerencia vários agentes, execução paralela, worktrees, remote access e plugins. A ideia de daemon/client é excelente para nós. O desktop, porém, usa Electron e o ecossistema amplo TypeScript/Expo/React.

# Produto Prumo proposto

```
Workspace
├── Agent Threads / Runs
├── Plan / Goal / Task view
├── Code Editor / Review
├── Diff / SCM
├── Terminal / Processes
├── Project Tree / Search
├── Evidence / Tests / Gates
├── Permissions / Approvals
├── Agents / Skills / Recipes
└── Observability / Costs / Context
```

# Diferenciais sobre simples wrappers

- agente próprio + suporte a agentes externos;
- Goals/Plans/Tasks first-class;
- evidence e quality gates visíveis;
- portable continuation;
- model routing explicável;
- native ACI;
- sandbox/worktree por Run;
- permission policy central;
- context manifest inspecionável;
- execução headless sem desktop;
- TUI consumindo o mesmo runtime.

# UX de multi-agent

Cada Run pode aparecer como uma unidade de trabalho, não apenas um chat. O usuário enxerga status, model, branch/worktree, tool activity, pending approval, tests, cost e blockers.

# Scope inicial do desktop

Priorizar: workspace selector, run/thread list, agent conversation, streaming, approvals, diff, files, terminal, tests/evidence e basic editor. Recursos IDE sofisticados entram conforme o Editor Engine estabiliza.

# Anti-meta

Evitar reproduzir uma aplicação web dentro de uma janela apenas para ter UI rapidamente se isso comprometer o objetivo central de leveza. A decisão native deve ser comprovada por benchmarks.
