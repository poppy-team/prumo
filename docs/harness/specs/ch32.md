<aside>
🔁

**Status: ACCEPTED.** Continuação entre agents/providers e acesso ao Knowledge Runtime usarão contratos tipados, pointer-first e versionados. Handoff não transfere transcript bruto nem estado privado do modelo; transfere identidade, canonical pointers, checkpoint, Context Manifest, pending effects e provenance. A Knowledge API é a única superfície coerente de locate/search/explain/context/delta/commit para agents e clients.

</aside>

# Objetivo

Fechar a fronteira que permite:

- trocar Agent/Provider dentro do mesmo Run/Thread;
- retomar depois de crash/restart;
- fazer handoff por quota/outage;
- sair do Plan Mode e iniciar Build;
- dar a qualquer client/agent acesso uniforme ao conhecimento sem conhecer SQLite, files ou Memory Atlas internals.

# Princípio

```
Portable continuation = canonical pointers + typed state + pending effects
```

Não:

```
"aqui estão 80k tokens de conversa, continue"
```

# Pointer-first

Arrays guardam IDs/refs compactos; full payload permanece onde pertence.

Exemplo:

```
DecisionRef D-042
EvidenceRef EV-991
ContextManifestRef CM-88
ArtifactRef A-551
```

O target busca conteúdo completo via Knowledge/Artifact APIs somente quando necessário.

# Continuation summary

Existe para acelerar bootstrap do target, mas é **derived** e nunca substitui canonical refs.

Campos candidatos:

```
what_was_requested
what_is_done
what_is_in_progress
what_failed
what_must_not_change
next_recommended_action
```

Summary mantém digest/version do builder e pode ser regenerada.

# Pending effects

Parte crítica para evitar duplicate side effects.

```
PendingEffect
├── id
├── kind
├── status
├── idempotency_key
├── started_at semantic/event ref
├── target
├── observable_effect
├── recovery_policy
└── evidence_ref optional
```

Kinds: process, file mutation, git operation, external tool, permission wait, package download, provider request, deployment future.

Antes de handoff, o source tenta atingir safe point; quando não consegue, o target recebe pending effects explicitamente.

# Safe points

Preferência de handoff:

1. entre Turns;
2. após ToolCall finalizado/observado;
3. após checkpoint de workspace;
4. depois de persistir KnowledgeDelta/Evidence.

Handoff emergencial pode acontecer fora de safe point, mas exige `pending_effects` + recovery state.

# Tipos de handoff

```
manual
agent_switch
provider_failure
quota_exhausted
capability_upgrade
review_handoff
planning_to_build
crash_recovery
resource_rebalance
```

A reason determina policy, não muda o schema.

# Planning → Build

`PlanningSession` não vira Run. Produz `PlanningHandoff` compatível com o mesmo envelope:

```
accepted Decisions
active Requirements/Constraints
Research refs
open Questions
compiled docs/artifacts
Goal/Plan/Task baseline
```

Então Run novo referencia o handoff como provenance.

# Cross-model/provider portability

Handoff não contém vendor-specific session semantics. Se target AgentProvider suporta resume nativo, seu session token fica em provider-owned opaque ref; o canonical Prumo Handoff continua suficiente para reconstruir em outro provider caso resume não seja possível.

# Integrity

`HandoffBundle` inclui:

```
canonical_state_revision
workspace_revision
digests of embedded compact projections
schema_version
created_from_checkpoint
```

Persistência usa atomic write/transaction. Bundle inválido não substitui last known-good continuation.

# Related

Graph-neighbor query tipada:

```

```

Depth baixo por default; traversal bounded.

# Explain

Responde deterministicamente quando possível:

```
Why is this here?
Where did this claim come from?
What superseded this decision?
Why was this context item selected?
```

Usa provenance, graph, manifests e reason codes — sem LLM quando não necessário.

# Context

API oficial para compilar contexto:

```

→ ContextManifest v2
```

Clients/agents não montam prompt/context manualmente a partir do Atlas.

# Affected

Impact analysis:

```
Affected(entity/change)
→ docs
→ contracts
→ tasks
→ artifacts
→ cached/index nodes
```

Reusa TraceabilityGraph + Documentation BuildGraph; mantém os grafos semanticamente distintos.

# KnowledgeDelta

Única forma estruturada de propor mutações de conhecimento provenientes de agents.

```
KnowledgeDelta
├── delta_id
├── source
├── base_revision
├── operations[]
├── evidence_refs[]
├── provenance
└── expected_effects
```

Operations:

```
add_record
update_record
supersede_record
add_relationship
remove_relationship
attach_evidence
change_status
promote_candidate
```

Não aceitar `write arbitrary markdown` como mutação canônica de Knowledge Runtime.

# ValidateDelta → CommitDelta

Fluxo obrigatório:

```
Agent proposal
→ ValidateDelta
   ├── schema
   ├── identity
   ├── authority
   ├── base revision
   ├── invariants
   ├── contradiction candidates
   ├── permission/policy
   └── affected calculation
→ preview
→ policy/review when required
→ CommitDelta
→ canonical append/mutation
→ DomainEvents
→ indexes/docs invalidation
```

# Optimistic concurrency

`base_revision`/expected digest evita lost update.

Se canonical state avançou:

```
conflict
→ rebase/revalidate
```

Não fazer last-write-wins para Decisions/Requirements/Claims importantes.

# Transaction boundary

Commit de um KnowledgeDelta é atômico logicamente. Derived work ocorre depois por event:

```
Commit canonical delta
→ KnowledgeChanged
→ update graph/index
→ invalidate Context cache
→ Documentation build impact
→ Memory/coverage derived updates
```

Se derived rebuild falha, canonical commit continua válido e derived layer fica marked stale/rebuild-needed.

# Authority mutation

Agent nunca eleva authority implicitamente.

Exemplo:

```
proposal → accepted
```

requer policy/actor autorizado quando status altera autoridade semântica.

Tiny Knowledge Worker só cria candidate/proposed records.

# Knowledge snapshots

Para eval/replay/handoff:

```
KnowledgeSnapshot
├── revision
├── manifest_digest
├── graph_revision
├── decision_ledger_revision
├── research_revision
└── memory_atlas_revision
```

Snapshot é lightweight pointer set, não cópia inteira do corpus.

# Read/write separation

Query path pode ser altamente otimizado/cacheado; write path é mais estrito.

```
Read:
fast / derived indexes / progressive disclosure

Write:
validated / revisioned / provenance-required / transactional
```

# Failure rules

- target capability mismatch → reject before session creation;
- missing mandatory ref → rebuild/fetch or block;
- stale workspace revision → reconciliation required;
- pending non-idempotent effect unknown → block automatic continuation;
- malformed bundle → use previous checkpoint;
- target provider unavailable → router may select another eligible AgentProvider.

# Retention

HandoffBundle é compact durable Run state; pode sobreviver transcript retention. Provider-native opaque session refs seguem suas próprias retention policies e não são necessários para portability.

# Segurança

- secrets não entram no bundle; usar secret refs/credential ownership;
- tool outputs grandes ficam por ArtifactRef;
- external content preserva trust class/data-only marker;
- privacy scopes acompanham refs;
- target recebe apenas capabilities/resources autorizados;
- bundle pode ser inspected sem revelar chain-of-thought.

# Evals

- resume success after crash;
- cross-provider continuation success;
- duplicate side-effect rate = zero target;
- mandatory state completeness;
- handoff token footprint;
- stale-ref detection;
- conflict/rebase correctness;
- planning→build fidelity;
- Knowledge API locate/search/context precision;
- invalid mutation rejection;
- provenance completeness.

# Decisões fechadas

- HandoffBundle typed/pointer-first;
- portable continuation não depende de transcript;
- pending effects são first-class;
- safe-point preferred handoff;
- Planning→Build usa handoff/provenance, não converte PlanningSession em Run;
- KnowledgeService é query/write API unificada;
- KnowledgeDelta é mutação estruturada;
- Validate→Commit obrigatório;
- optimistic concurrency por revision/digest;
- derived rebuild é event-driven após canonical commit;
- authority nunca é elevada implicitamente por model output.
