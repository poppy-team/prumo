# Objetivo

Mapear o que já existe no Prumo para evitar reimplementar como se estivéssemos começando um coding agent do zero.

# Estado herdado

O Prumo v0.5 já é uma distribuição Go single-binary e possui uma arquitetura separada em Knowledge, Control, Quality, Execution e Integration Planes.

| Capacidade | Estado | Como entra no Code Agent |
| --- | --- | --- |
| Goals / Plans / Tasks | forte | fonte de intenção e decomposição |
| Workforce: agents/skills/recipes | amplo; hardening em andamento | especialização e composição |
| Run lifecycle | fundação real | lifecycle do trabalho |
| ExecutorSession | existente | sessão concreta de modelo/harness |
| Checkpoint / ContinuationRecord | existente | resume cross-session/model |
| Budget Envelope | fundação | tokens/custo/tools/time |
| Context Compiler | MVP determinístico | precisa virar context engine de código |
| Model Registry/Router | MVP | falta runtime/provider streaming |
| Tool Gateway | fundação | falta execução ACI completa |
| MCP governance | fundação | falta client/runtime first-class |
| Environment | local + worktree | falta sandbox real |
| Egress/secrets | fundação | enforcement por invocation |
| Observability | eventos estruturados | expandir para turn/model/tool spans |
| Automation/DLQ | semente | depois do agent loop |
| Adapters de harness | múltiplos | manter compatibilidade |

# Lacunas que definem a fronteira do Harness

- `ModelProvider` real: request, streaming, tool calls, structured output, usage, cancellation;
- `AgentRuntime`: Turn/Message/Action/Observation/Stop;
- Conversation/Thread model persistível;
- native Coding ACI;
- execution/approval protocol por tool call;
- sandbox provider real;
- PTY persistente;
- context/repository intelligence v2;
- trajectory replay/evals;
- client event streaming;
- Agent Server/ACP depois do modo headless.

# Regra de arquitetura

Não mover lógica canônica para os novos clientes. O desktop não decide qual recipe usar; a TUI não implementa outra taxonomia de risk; o ACP adapter não reinterpreta permissions. Essas decisões pertencem ao Core/Harness.
