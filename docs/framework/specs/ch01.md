# 01 — Stack Go, Clean Code e Migração do Core Python

> Authority: canonical specification.
> Logical ID: PART1-CH-01
> Source: Notion Living Book (3d59bb7d023f81c5a804f589d8daf696)
> Status: Especificação de engenharia do Framework (Capítulo 01).


O Atlas v0.4 terá **Go como linguagem oficial do core e CLI**. Python deixa de ser dependência obrigatória em runtime.

## Stack alvo

- Go: core, CLI, validators, resolvers, compilers, documentation engine, planning, adoption, events, experience, traceability, SQLite e MCP.
- Markdown + JSON + JSON Schema: contratos canônicos.
- Git: armazenamento durável e histórico.
- SQLite: índice derivado local.
- TypeScript: apenas adapters que precisem rodar dentro de hosts JS/TS, especialmente OpenCode.
- Python: apenas legado transitório, oracle de compatibilidade e scripts de manutenção excepcionalmente justificados.

## Regras de implementação Go

- `gofmt` obrigatório.
- `go test ./...` obrigatório.
- `go vet ./...` obrigatório em CI.
- `staticcheck` recomendado como gate de qualidade.
- Evitar packages “utils”, “common”, “helpers” sem domínio claro.
- Evitar arquivos gigantes; organizar por responsabilidade coesa.
- `context.Context` apenas em operações que realmente atravessam boundaries de cancelamento/deadline.
- Erros envelopados com `%w` quando a causa deve ser preservada.
- Sem `panic` para erro de usuário/configuração.
- Interfaces pequenas, próximas do consumidor.
- Preferir structs imutáveis por convenção onde fizer sentido.
- Zero CGO por padrão para preservar distribuição simples.
- `database/sql` sem ORM na primeira implementação.
- `embed.FS` para schemas/templates/resources que precisem viajar com o binário.

## Migração por paridade, não rewrite cego

### Fase A — Freeze comportamental v0.3

- congelar os contratos observáveis relevantes;
- catalogar comandos, códigos de saída, schemas e golden outputs;
- impedir features v0.4 de entrar no Python salvo correções críticas.

### Fase B — Foundation Go

Portar carregamento de projeto, schemas, config, recursos embarcados, tipos do protocolo e infraestrutura de erros.

### Fase C — Deterministic Core

Portar validator, resolver, model policy, workforce resolution, Goal v2, hashing/locking, amendments e state transitions.

### Fase D — CLI parity

Preservar comportamento público de `atlas init`, `doctor`, `explain`, `goal`, `compile` e comandos relevantes.

### Fase E — Compiler parity

Reproduzir Codex, Claude Code e Generic adapters existentes; adicionar OpenCode como target de primeira classe somente após a base estar estável.

### Fase F — Conformance 100%

Python v0.3 funciona como oracle. Inputs idênticos devem produzir resultados equivalentes semanticamente.

### Fase G — Go becomes canonical implementation

Marcar Python deprecated, remover dependência de instalação e congelar scripts antigos.

### Fase H — v0.4 features

Só então implementar Living Plan, Documentation Contracts, Adoption, Experience e novos harnesses.

## Critérios para apagar Python legado

- conformance Go = 100% dos contratos críticos;
- releases Go disponíveis nas plataformas alvo;
- docs de instalação não dependem de Python;
- pelo menos um ciclo de release sem regressão crítica;
- scripts legados classificados como removidos, portados ou permanentemente opcionais.

## Decisão sobre `fix_schemas.py` e `write_docs.py`

Cada script deve passar por triagem:

- função permanente do Atlas -> portar para Go;
- migração one-shot já cumprida -> remover;
- ferramenta de maintainer rara e independente -> pode permanecer Python, mas não pode ser necessária para uso normal do Atlas.
