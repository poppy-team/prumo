# Network condition matrix

Providers devem poder variar:

- latency;
- jitter;
- packet loss;
- duplication;
- reordering quando stack suportar;
- bandwidth limits;
- temporary disconnect;
- reconnect;
- client pause/background;
- server restart/failover quando aplicável.

# Core scenarios

- join/leave;
- reconnect;
- late join;
- map transition;
- respawn;
- inventory/state replication;
- simultaneous actions;
- ownership transfer;
- server authority;
- cheat-attempt boundaries;
- high player count;
- long session;
- host migration quando existir.

# Desync detection

Quando arquitetura permitir, gerar state hashes ou snapshots comparáveis por tick/window e capturar first divergence.

Evidence:

- tick;
- client/server state;
- input history;
- network conditions;
- seed;
- replication events.

# Adversarial network profiles

Não testar somente `good` e `average`. Manter profiles versionados como:

- good;
- residential average;
- mobile unstable;
- high latency;
- high packet loss;
- jitter burst;
- reconnect storm;
- custom project-specific.

Unreal Network Emulation documenta lag, jitter e packet loss e recomenda condições severas para encontrar problemas que redes ideais escondem.

Fonte: [https://dev.epicgames.com/documentation/unreal-engine/using-network-emulation-in-unreal-engine](https://dev.epicgames.com/documentation/unreal-engine/using-network-emulation-in-unreal-engine)

# Scale testing

Separar:

- simulation scale: milhares de clients sintéticos;
- protocol/load scale;
- full game clients;
- long-running server soak.

Métricas:

- server tick time;
- bandwidth/client;
- replication backlog;
- CPU/memory;
- matchmaking latency;
- error/disconnect rate;
- persistence consistency.

# Security

Multiplayer profile ativa automaticamente threat modeling para authoritative state, RPC validation, rate limiting, trust boundaries, replay/forgery e exploit surfaces. Nunca confiar em estado crítico vindo do client sem regra explícita.
