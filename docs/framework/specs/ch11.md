A instalação deve ser trivial e reversível. O usuário não deve precisar gerenciar Python, venv ou Node para usar o Atlas Core.

## Distribuição oficial

Publicar binaries assinados por release para:

- Linux amd64;
- Linux arm64;
- macOS amd64 se ainda relevante;
- macOS arm64;
- Windows amd64;
- Windows arm64 quando toolchain/ecossistema justificar.

## Canais de instalação

### Bootstrap script oficial

```bash
curl -fsSL https://.../install.sh | sh
```

O script deve baixar release pré-compilada, verificar checksum/assinatura e instalar em path previsível.

### Homebrew

`brew install project-atlas/tap/atlas`

### Scoop/WinGet

Planejar package para Windows.

### Arch/AUR ou packages da comunidade

Suportar, mas não tornar requisito da release inicial.

### `go install`

Oferecer para desenvolvedores quando apropriado, mas não como experiência principal do usuário final.

## Diretórios

Separar claramente:

- binary;
- config global;
- cache;
- derived database;
- logs;
- connector state;
- project-local state.

Seguir convenções XDG em Unix-like quando possível.

## `atlas install`

Opcionalmente configura integrações após o binário existir:

```
atlas install connector opencode
atlas install connector gemini
```

## `atlas setup`

Wizard amigável para:

- detectar harnesses instalados;
- selecionar integrações;
- escolher global/project scope;
- validar PATH;
- executar doctor.

## `atlas update`

- checar canal stable/pre-release;
- download atômico;
- checksum/signature;
- rollback em falha;
- não alterar projeto silenciosamente.

## `atlas uninstall`

Deve remover o Atlas Core com segurança. Nunca apagar dados de projeto automaticamente.

### Opções

```
atlas uninstall
atlas uninstall --connectors
atlas uninstall --purge-cache
atlas uninstall --purge-global-config
```

Mesmo `--purge` não deve apagar `.ai/`, docs, Goals ou outros dados versionados de projetos.

## Connector uninstall

Cada connector possui **Cleanup Manifest** registrando exatamente o que criou/modificou.

Ao remover:

- retirar somente blocos/configs que o Atlas possui;
- preservar customizações do usuário;
- remover symlinks/plugins gerados;
- restaurar backup somente quando ownership e hash provarem segurança;
- apresentar leftovers quando não for possível remover automaticamente.

## Installation manifest

Registrar globalmente:

```json
{
  "atlas_version": "0.4.x",
  "binary_path": "...",
  "connectors": {},
  "created_paths": [],
  "managed_config_fragments": []
}
```

## Idempotência

Rodar install/setup duas vezes deve convergir ao mesmo estado.

## Project initialization

`atlas init` não instala harness global. Apenas cria projeto Atlas canônico e, se pedido, compila config project-local.

## Recomendação adicional — Portable mode

Oferecer `atlas --home ./path` ou variável equivalente para ambientes CI, USB/devbox e testes sem tocar configuração global.
