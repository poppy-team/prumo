OpenCode será o primeiro harness nativo de nova geração do Atlas. Não haverá fork inicialmente. O Atlas deve explorar agents, skills, commands, permissions, plugins, lifecycle hooks e MCP do host.

## Target

Substituir o adapter genérico por:

```
atlas compile --target opencode
```

## Primary agent `atlas`

Responsável por intent routing e orchestration, não por executar tudo sozinho.

Fluxo:

```
request -> detect Atlas -> classify intent/risk -> resolve goal/task -> resolve recipe/workforce/skills -> minimal context -> delegate -> gates -> docs delta -> evidence -> state
```

## Plugin `atlas.ts`

Deve permanecer fino e chamar o Atlas Core.

### Responsabilidades

- lifecycle capture;
- context injection;
- tool preflight/guard;
- post-tool evidence capture;
- compaction/continuation context;
- expose Atlas custom tools;
- bridge de session/handoff.

### Não pode

- reimplementar Goal lifecycle;
- decidir workforce por conta própria;
- modificar canonical schemas;
- criar estado durável fora do Atlas.

## Tool guard

Antes de writes/shell sensível:

```
OpenCode tool -> atlas validate-tool -> allow / deny / require confirmation
```

Exemplos de deny determinístico:

- Implementer tenta modificar acceptance criteria locked.
- Agente read-only tenta write.
- alteração fora do escopo de task quando policy exige scope.
- tentativa de editar documento protegido sem workflow adequado.

## Context Governor

Injetar somente cápsula mínima: projeto, Goal, Task, invariants, relevant docs e pointers de expansão.

## Commands

Sugestões:

- `/atlas-plan`
- `/atlas-implement`
- `/atlas-docs`
- `/atlas-review`
- `/atlas-status`
- `/atlas-adopt`
- `/atlas-trace`
- `/atlas-release`

O usuário comum não precisa invocar; são escape hatches explícitos.

## Global vs Project

Instalação global disponibiliza o harness. Configuração project-local define comportamento específico e versionável.

## Compatibilidade OpenCode 1/2

Como OpenCode 2 está em evolução, o connector deve possuir capability detection e versões separadas quando necessário. Nunca depender de uma API beta sem declarar compatibilidade.
