## Objetivo

Transformar o Event Protocol em automação confiável sem começar por um scheduler autônomo complexo.

## Modelo

```
event → rule → conditions → actions → evidence
```

Exemplos: dependency.changed → SCA; public-api.changed → compatibility review; session.ended → consolidation/handoff; release.requested → release gates; grammar.changed → compiler regression profile.

## Automation Contract

Campos: id/version, trigger, conditions, actions, approval policy, timeout, retry policy, concurrency key, budget, environment, failure policy e ownership.

## Idempotência

Cada execution possui run/idempotency key. Reprocessar o mesmo event não deve duplicar side effects.

## Retry e cancellation

A automação herda a failure taxonomy do Run Engine. Cancellation propaga e cleanup é obrigatório quando aplicável.

## Concurrency keys

Evitar duas automações alterando simultaneamente o mesmo canonical artifact ou release state.

## Dead Letter Queue

Depois de retries esgotados ou erro não retryable, enviar item para DLQ com event, failure, attempts e recovery hints.

CLI alvo:

```bash
atlas automation list
atlas automation explain <id>
atlas automation failures
atlas automation retry <failure>
```

## Scheduler futuro

Daily/weekly/nightly entra somente após event-driven workflows estarem estáveis. CI/Git/harness events entregam maior valor inicial com menor risco.
