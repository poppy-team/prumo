O Atlas não incorpora uma engine. Cada engine expõe providers sob contratos comuns.

# Unreal Engine adapter

Providers candidatos:

- Automation Framework;
- Functional Testing;
- Automation Driver;
- Screenshot Comparison;
- Gauntlet;
- Network Emulation;
- Unreal Insights/performance;
- commandlets/content validation.

A Automation Framework atual documenta unit, feature, smoke, content stress e screenshot comparison. Gauntlet é adequado para orquestrar sessões complexas, inclusive múltiplos clients/server e target platforms.

Fontes:

- [https://dev.epicgames.com/documentation/unreal-engine/automation-test-framework-in-unreal-engine](https://dev.epicgames.com/documentation/unreal-engine/automation-test-framework-in-unreal-engine)
- [https://dev.epicgames.com/documentation/unreal-engine/gauntlet-automation-framework-overview-in-unreal-engine](https://dev.epicgames.com/documentation/unreal-engine/gauntlet-automation-framework-overview-in-unreal-engine)

# Unity adapter

Providers candidatos:

- Unity Test Framework Edit Mode;
- Play Mode;
- target platform runs;
- Performance Testing API;
- Memory Profiler;
- graphics/visual provider quando superfície oficial adequada estiver disponível;
- network simulation/provider conforme stack multiplayer usada.

Fonte: [https://docs.unity3d.com/6000.0/Manual/com.unity.test-framework.html](https://docs.unity3d.com/6000.0/Manual/com.unity.test-framework.html)

# Godot adapter

Core/engine development possui unit tests C++ com doctest. Para projetos, o Atlas deve suportar:

- headless execution;
- scene/script runners;
- profiler/visual profiler extraction quando possível;
- community providers opcionais como GdUnit4 ou GUT, nunca fingindo que são parte oficial da engine.

GdUnit4 oferece GDScript/C#, scene runner, fuzzing, mocking e CI/JUnit; o Atlas deve tratá-lo como provider third-party versionado.

Fontes:

- [https://docs.godotengine.org/en/stable/tutorials/editor/command_line_tutorial.html](https://docs.godotengine.org/en/stable/tutorials/editor/command_line_tutorial.html)
- [https://github.com/godot-gdunit-labs/gdUnit4](https://github.com/godot-gdunit-labs/gdUnit4)
- [https://github.com/bitwes/Gut](https://github.com/bitwes/Gut)

# Engine-agnostic runtime adapter

Para engines próprias/frameworks:

interfaces ideais:

```
game_test boot --headless
game_test run <scenario>
game_test replay <file>
game_test snapshot
game_test metrics --json
game_test screenshot
game_test shutdown
```

O Atlas pode gerar um pequeno Test Bridge SDK por linguagem/runtime, sem impor arquitetura interna.

# Capability negotiation

Cada engine/provider anuncia capacidades como:

```
game.headless
game.replay
game.fixed_timestep
game.screenshot
game.profiler.cpu
game.profiler.gpu
game.network.emulation
game.multi_instance
game.scene_tests
game.asset_validation
```

Quality Orchestrator adapta o plano ao que realmente existe.
