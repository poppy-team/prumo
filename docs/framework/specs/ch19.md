# 19 — Registro Consolidado de Decisões v0.4

# Decisões aceitas

## D-001 — Go Core

Go substitui Python como runtime oficial a partir do v0.4, com migração por conformance.

## D-002 — Clean Code permanente

Implementação deve seguir Clean Code pragmático e evitar overengineering.

## D-003 — Canonical formats preservados

Git + Markdown + JSON + JSON Schema continuam independentes do runtime Go.

## D-004 — SQLite derivado

SQLite serve a índices, busca, graph e runtime cache; deve ser reconstruível.

## D-005 — TypeScript somente na borda

OpenCode plugin pode ser TS; regras de protocolo não.

## D-006 — Documentation Contracts

Completude documental será definida por conhecimento obrigatório, não existência de arquivos.

## D-007 — Documentation Profiles

Capabilities ativam packs proporcionais ao projeto.

## D-008 — UI Documentation Pack profundo

Wireframes semânticos, layout, spacing, tokens, cores, tipografia, components, states, accessibility, localization e visual tests fazem parte da especificação quando aplicáveis.

## D-009 — Living Plan

Planejamento por entrevista incremental atualiza docs conforme decisões são aceitas.

## D-010 — Adoption Engine

Projetos existentes são mapeados e adaptados incrementalmente sem reestruturação destrutiva automática.

## D-011 — Engineering Narrative

Implementation Journal registra síntese útil da trajetória sem chain-of-thought.

## D-012 — Traceability

Requirements/decisions/code/tests/docs/evidence devem poder ser ligados por typed edges.

## D-013 — Experience taxonomy

Canonical, Historical, Episodic e Experiential memory são conceitos distintos.

## D-014 — Experience proposals

Aprendizado transversal nunca altera conhecimento crítico silenciosamente.

## D-015 — Handoff Protocol

Sessões/agentes trocam estado estruturado, não dependem de transcript.

## D-016 — ai-memory como inspiração/provider

Incorporar conceitos; permitir provider experimental; não acoplar Atlas ao formato interno do projeto.

## D-017 — OpenCode first native harness

Sem fork inicial; plugin + agents + skills + commands + hooks + Atlas Core.

## D-018 — Connector Contract

Todo harness declara capabilities, enforcement level, protocol compatibility e cleanup.

## D-019 — Easy lifecycle

Install/update/uninstall são features oficiais; nenhum project data é apagado por uninstall padrão.

## D-020 — Connector cleanup ownership

Atlas remove somente artefatos que consegue provar que possui.

## D-021 — No v0.4 Python-first

Novas features grandes entram somente depois da paridade Go v0.3.

## D-022 — Generic fallback preservado

Sempre existirá uma integração genérica para harnesses sem primitives nativas.

## D-023 — Harness roadmap

Após OpenCode: elevar Claude Code/Codex e implementar Gemini CLI; Copilot CLI e Kiro são prioridades seguintes.

## D-024 — Deterministic before probabilistic

Validação, policy e state transitions não devem depender de LLM quando podem ser determinísticos.

## D-025 — Installation portability

Single binary, zero CGO por padrão e nenhum Python/Node requerido pelo Atlas Core.

# Decisões deliberadamente adiadas

- servidor central/team runtime obrigatório;
- embeddings como requisito;
- dashboard web completo;
- SDK Go público;
- fork de qualquer harness;
- graph database externo;
- ORM.

# Critério para reabrir decisão

Uma decisão aceita só deve ser reaberta mediante nova evidência técnica, incompatibilidade de plataforma, custo operacional significativo ou mudança material nos requisitos do Atlas.
