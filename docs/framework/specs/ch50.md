## Distinções fundamentais

- **Physical Context Window:** capacidade anunciada pelo provider/model.
- **Effective Context Window:** faixa considerada confiável pelos evals Atlas.
- **Task Context Budget:** quanto a tarefa realmente deve receber.

Janela maior não implica enviar mais contexto.

## Context Compiler

Entrada: intent, Goal, Task, risk, **executor/model capabilities atuais**, skills, repository state, canonical knowledge, working state, Continuation/Handoff refs quando existirem e tool results.

Na troca de `ExecutorSession`, model ou harness, o Atlas **recompila** um Context Manifest adequado ao novo executor. Não reutiliza cegamente o prompt/context package da sessão anterior. Portable Continuation fornece estado e pointers; Context Compiler decide o contexto efetivo para a nova sessão.

Pipeline:

```mermaid
flowchart LR
    C["Candidates"] --> A["Authority"] --> F["Freshness"] --> R["Relevance"] --> D["Deduplicate"] --> T["Token Cost"] --> P["Priority Pack"] --> M["Context Manifest"]
```

## Context Manifest

Toda chamada importante deve poder informar fontes incluídas/excluídas, estimativa de tokens, authority/trust, freshness e motivo de seleção. `atlas context explain` não revela chain-of-thought; mostra decisões determinísticas/estruturadas do compiler.

## Tool-output budgets

Outputs grandes são resumidos + pointer + continuation. Raw output fica fora do prompt sempre que possível. Expansão é explícita e localizada.

## Context pressure

Estados conceituais: `healthy`, `pressure`, `compact`, `critical`. Thresholds são provider/model-profiled, não números universais.

Sob pressão: dedupe, collapse de resultados, pointer-over-payload, summaries de working state. Em compact: checkpoint estruturado e reconstrução de contexto fresco. O mesmo princípio vale para troca de model/harness/session: fresh context compilation sobre a mesma Run, não replay da memória privada do executor anterior.

## Prompt/cache awareness

Preservar prefixos estáveis e ordering determinístico de policies/tools quando provider oferece caching. Separar: static policy prefix, project-stable prefix e dynamic task state.

## Retrieval policy

Structural lookup → FTS/graph → embeddings apenas quando benchmark demonstrar benefício. Context Compiler deve contabilizar ganho por token, não somente similaridade.

## Evals

Medir context precision/recall, task success, tokens/task, stale-context rate, contradiction inclusion, compression loss e cache reuse quando observável.
