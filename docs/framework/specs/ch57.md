## Problema

Skills, connectors, test providers, experience providers e blog adapters criam um ecossistema multi-runtime. Não espalhar `npm`, `pip`, `cargo` e downloads manuais pelos projetos.

## Atlas Package

Tipos iniciais: `skill`, `connector`, `test-provider`, `experience-provider`, `publication-adapter`.

Manifest: id/version/type, Atlas protocol range, platform, dependencies, permissions, runtime requirements, checksum/signature/provenance e install/cleanup strategy.

## atlas.lock

Lockfile derivado/canônico conforme policy, registrando versões resolvidas e integridade dos packages. Objetivo: duas máquinas obtêm o mesmo conjunto lógico de capacidades.

## Runtime Manager

Runtimes auxiliares são instalados sob `$ATLAS_HOME/runtimes/...`, isolados do projeto sempre que possível. Ex.: provider Playwright pode carregar Node/packages/browsers próprios sem tornar Node dependência do Atlas Core.

## Installation ownership

Registrar se o core veio de Homebrew, WinGet/Scoop, script oficial, package distro ou build dev. Self-update respeita o owner: instalação gerenciada por package manager não é sobrescrita silenciosamente.

## Comandos alvo

```bash
atlas package list
atlas package install <id>
atlas package update <id>
atlas provider install <id>
atlas runtime list
atlas runtime gc
atlas repair
```

## Offline bundles

Planejar export/import de packages/runtimes assinados para CI isolado ou ambientes sem internet.

## Supply chain

Verificação de hash/provenance antes de ativar package. Permissions declaradas entram no trust review.
