# Selection guidance

### FSM

Use para comportamento pequeno, explícito e previsível. Evitar explosão combinatória de estados.

### Behavior Tree

Bom para authoring hierárquico, reatividade e debugging visual. Exigir testes de decorators, interruption/abort semantics e subtrees críticas.

### Utility AI

Adequado para decisões graduais e seleção baseada em scores. Exigir ranges, normalization, sensitivity tests e tie-breaking definido.

### GOAP / planning / HTN

Adequado quando ações combinam preconditions/effects e objetivos de médio prazo. Testar solvability, plan cost, loops e fallback.

### Influence maps / tactical query

Úteis para controle espacial, threat, cover, territory e posicionamento.

### MCTS / search

Útil em decision spaces simuláveis e jogos combinatórios; custo deve ser budgetado.

### ML/RL

Somente quando comportamento aprendido realmente oferece benefício. Exigir model/version provenance, deterministic fallback quando necessário, inference budget, out-of-distribution handling e observabilidade.

# AI Test Matrix

Para cada archetype relevante:

- spawn/init válido;
- perception accuracy;
- target selection;
- decision transition;
- action completion;
- interruption;
- navigation reachability;
- obstacle avoidance;
- stuck recovery;
- target lost/reacquired;
- group coordination;
- friendly-fire rules;
- resource constraints;
- animation/action synchronization;
- save/load;
- network replication quando aplicável;
- perf budget por NPC e por crowd.

# AI invariants

Exemplos:

- agente nunca usa informação não percebida, salvo design explícito;
- path selecionado termina em região navegável;
- ação só executa com preconditions satisfeitas;
- planner termina dentro do budget;
- utility score permanece em domínio definido;
- comportamento possui fallback seguro;
- nenhum agente permanece `stuck` acima do threshold sem recovery event.

# AI observability

Runtime de debug deve poder expor:

- current state/node/action;
- reason/score da decisão;
- blackboard/knowledge relevante;
- perceived entities;
- path/nav corridor;
- planner search statistics;
- utility considerations;
- cooldowns/resources;
- event trace.

Isso é crítico: IA impossível de explicar é muito mais difícil de testar.

# Research baseline

O panorama de AI/CI em games cobre comportamento, search/planning, player modeling, PCG, believable agents e AI-assisted design. O Game AI Pro oferece conhecimento de produção sobre behavior trees, utility, HTN, pathfinding, crowds, AI LOD, automated AI testing e balanceamento.
