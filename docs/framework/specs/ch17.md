## `internal/app`

Use cases/orchestration de aplicação. Commands e adapters chamam essa camada.

## `internal/protocol`

Domínio estável. Não conhece Cobra, filesystem concreto, OpenCode ou SQLite.

## `internal/documentation`

Não deve se tornar um “CMS”. Cuida de contratos, coverage, semantic roles e deltas.

## `resources`

Conteúdo embarcável ou distribuído com o Atlas. Considerar `go:embed`.

## `integrations`

Pode conter generated templates e código do host. TypeScript do OpenCode fica isolado aqui.

## `testdata`

Fixtures complexas, repositórios sintéticos e golden inputs.

## Regras para packages

- começar consolidado e quebrar somente quando responsabilidade justificar;
- sem package por tipo/arquivo;
- sem circular dependencies;
- evitar nomes genéricos;
- `internal` protege API prematura.

## API pública Go

Não criar SDK Go público no primeiro milestone. Primeiro estabilizar CLI/machine protocol; expor packages públicos somente quando consumidores externos reais existirem.
