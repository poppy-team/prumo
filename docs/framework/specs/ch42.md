# Editor contracts

Testar:

- new/open/save/save-as;
- dirty state;
- autosave/recovery;
- undo/redo;
- selection;
- multi-selection;
- copy/paste/duplicate;
- drag-drop;
- import/reimport;
- export;
- viewport state;
- keybindings;
- workspace/layout persistence;
- recent files;
- crash recovery;
- project migration.

# Asset pipeline

Cada importer/exporter pode possuir corpus de fixtures:

- minimal valid;
- representative;
- large/stress;
- malformed;
- legacy versions;
- edge-case encoding;
- missing references;
- circular/invalid refs quando formato permitir.

Verificar:

- parser safety;
- semantic validity;
- metadata preservation;
- coordinate/unit conversion;
- texture/color-space;
- skeleton/bone mapping;
- animation timing;
- material assignments;
- deterministic reimport quando esperado;
- round-trip tolerance quando aplicável.

# Content validation

Executar gates antes de release:

- missing assets;
- invalid refs;
- unsupported formats;
- duplicate IDs;
- oversized textures/meshes;
- forbidden compression/settings;
- invalid collision meshes;
- broken nav data;
- missing LODs quando required;
- shader compile failures;
- platform-incompatible assets.

# Project file format

Aplicar princípios de protocolo do próprio Atlas:

- schema/version;
- migration;
- forward/backward compatibility policy;
- corruption handling;
- atomic writes;
- backup/recovery;
- unknown-field policy;
- fuzzing de loaders.

# Undo/redo testing

Toda operação destrutiva/editorial relevante deve, quando aplicável:

1. aplicar;
2. verificar estado;
3. undo;
4. comparar estado anterior;
5. redo;
6. comparar estado aplicado.

# GUI Test Bridge

Reutilizar Native Desktop GUI Test Bridge para fluxo externo e APIs internas/headless para comportamento profundo. Não depender só de mouse coordinates.
