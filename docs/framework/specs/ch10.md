OpenCode é o primeiro harness nativo, não o centro do Atlas. Todos os conectores obedecem a um contrato comum e anunciam capabilities.

## Connector Contract

Todo connector deve declarar:

- `id` e version;
- supported Atlas protocol range;
- host/harness versions suportadas;
- primitives disponíveis;
- context injection mechanism;
- agent/subagent support;
- skill support;
- command support;
- pre/post tool hooks;
- blocking capability;
- session lifecycle events;
- compaction/resume support;
- MCP support;
- permission model;
- config locations;
- install/uninstall strategy;
- cleanup manifest.

## Enforcement levels

- **Level 0 — Prompt only:** instruções, sem enforcement.
- **Level 1 — Generated configuration:** agents/skills/rules nativos.
- **Level 2 — Lifecycle integration:** hooks/events/context.
- **Level 3 — Guarded execution:** pode bloquear tool calls e validar writes.
- **Level 4 — Full native harness:** lifecycle, agents, skills, guards, evidence e handoffs integrados.

O Atlas deve mostrar o enforcement real de cada connector.

## Roadmap recomendado

### Tier A — Primeira classe

1. **OpenCode** — primeiro full-native connector.
2. **Claude Code** — forte ecossistema de hooks/subagents/skills/MCP; evoluir compiler existente para harness completo.
3. **Codex** — elevar adapter existente conforme primitives suportadas, mantendo AGENTS/skills/MCP e mecanismos oficiais.
4. **Gemini CLI** — prioridade alta porque possui extensions, skills, MCP e hooks síncronos que podem injetar contexto e bloquear ações.

### Tier B — Alto valor

1. **GitHub Copilot CLI / Coding Agent** — custom agents, skills e MCP; bom para repositórios GitHub e workflows de equipe.
2. **Kiro CLI/IDE** — steering, specs, custom agents, MCP e hooks de lifecycle/tool, incluindo gates pre-tool e pós-task.
3. **VS Code Agent ecosystem** — adapter focado em arquivos de agente/rules/skills portáveis onde a superfície for estável.

### Tier C — Integrações oportunísticas

- Cursor;
- Continue;
- Cline/Roo Code;
- Windsurf;
- JetBrains AI surfaces;
- outros harnesses com protocolo suficientemente estável.

## Critérios para promover connector a Tier A

- API/config pública documentada;
- hooks ou primitives suficientes para enforcement útil;
- adoption relevante;
- testes automatizáveis;
- política clara de versionamento;
- possibilidade de uninstall/cleanup determinístico.

## Generic adapter nunca desaparece

Manter um target genérico baseado em `AGENTS.md`/instructions/MCP como fallback universal.

## Recomendação adicional — Connector Test Kit

Cada connector deve passar uma suíte comum:

- install idempotency;
- compile determinism;
- config merge safety;
- scope enforcement;
- context injection;
- blocked write scenario;
- handoff round-trip;
- uninstall cleanliness;
- host-version compatibility.
