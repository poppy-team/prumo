## Machine interface

Todos os comandos usados por plugins devem possuir `--json` ou namespace interno versionado.

### Envelope recomendado

```json
{
  "protocol_version": "1",
  "ok": true,
  "data": {},
  "diagnostics": [],
  "warnings": []
}
```

### Error envelope

```json
{
  "protocol_version": "1",
  "ok": false,
  "error": {
    "code": "ATLAS_GOAL_LOCKED",
    "message": "...",
    "details": {}
  }
}
```

## Exit code policy

Definir conjunto pequeno e estável: success, validation failure, policy denied, configuration error, unavailable capability, internal error. Detalhe vai no JSON, não em dezenas de códigos de processo.

## Output discipline

- stdout machine-readable quando `--json`;
- diagnostics/logs em stderr quando necessário;
- sem ANSI em JSON;
- timestamps e paths normalizados;
- deterministic ordering quando output é golden-testable.

## Recomendação adicional — dry-run universal

Operações destrutivas ou de migração devem suportar `--dry-run` quando tecnicamente possível, exibindo files/config fragments/knowledge state afetados.
