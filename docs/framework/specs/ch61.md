# 61 — Atlas Harness Eval Suite, Canary e Runtime Quality Metrics

> Authority: canonical specification.
> Logical ID: PART1-CH-61
> Source: Notion Living Book (3d59bb7d023f8183a541dfa19216d468)
> Status: Especificação de engenharia do Framework (Capítulo 61).


## Objetivo

Testar o comportamento do harness inteiro, não apenas packages Go e skills individuais.

## Scenario corpus inicial

- tarefa pequena para medir overhead;
- repo grande/100k+ LOC;
- contexto sob pressão e compaction;
- long-running migration + resume;
- provider 429/timeout/5xx;
- ambiguous side effect;
- malicious README/prompt injection;
- conflicting skills/policies;
- stale/contradictory docs;
- flaky tests;
- hard budget exhaustion;
- connector crash;
- model alias drift;
- concurrent agents no mesmo scope.

## Métricas

Task completion, policy violations, context precision/recall, tokens/cost per task, unnecessary tool calls, skill activation precision/recall, wrong-tool rate, resume success, recovery success, evidence completeness, false pass, time-to-diagnosis e security containment.

## Baseline comparison

Toda heurística grande (Context Compiler, router, workforce, compaction) é comparada com baseline. Não promover mudança apenas porque parece elegante.

## Canary

Nova versão de model, connector ou resolver: shadow eval → canary subset → promote/rollback. Critical regressions bloqueiam promoção.

## Harness conformance

Conformance do protocol + behavior eval são complementares: JSON correto não garante agente útil; alta task success não permite violar invariants.

## Dogfood

O próprio desenvolvimento do Atlas fornece scenarios reais, desde que fixtures/evals sejam estabilizados e não dependam de narrativa privada das sessões.
