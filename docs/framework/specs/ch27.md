# Test taxonomy

## Deterministic unit/component

Lexer, parser, AST, type operations, IR passes, diagnostics builders, formatter pieces.

## Regression

Cada bug corrigido ganha caso mínimo quando possível. Suites por categoria preservam bug history.

## Golden / snapshot diagnostics

Input + expected diagnostics/spans/suggestions. Mudanças de output precisam review explícito para evitar atualização cega de goldens.

## Parse / print / format properties

Round-trip e idempotência quando semanticamente aplicável: parse→print→parse; fmt(fmt(x)) == fmt(x); AST invariants.

## Property-based generation

Gerar programas/ASTs válidos e inválidos respeitando grammar/type constraints.

## Differential testing

Executar casos semanticamente equivalentes em referências/versões/backends/optimization levels e comparar resultados. Csmith/YARPGen demonstram valor desse padrão para achar miscompilations.

## Metamorphic / EMI

Gerar variantes cujo comportamento esperado deve permanecer equivalente sob inputs especificados. Útil quando não há oracle externo simples.

## Fuzzing

Targets isolados para lexer/parser/type checker/serializer/bytecode/verifier/linker/protocols; coverage-guided quando possível.

## Sanitizers / UB

Para C/C++ runtimes/tooling: ASan/UBSan e outros sanitizers aplicáveis. Rust unsafe: Miri e sanitizers quando apropriado.

## Translation validation

Para transformations/optimizers com IR formalizável, considerar Alive2-like refinement/SMT validation ou provider equivalente; não exigir em toda linguagem.

## Cross-mode matrix

Debug/release, optimization levels, feature flags, target architectures, host OS/toolchain versions.

# Referências de projetos maduros

LLVM usa lit/FileCheck e múltiplas suites; Rust compiler possui UI/codegen/MIR/assembly/debuginfo/incremental/run-make etc.; Go fornece fuzzing coverage-guided nativo; Csmith/EMI/YARPGen mostram differential/metamorphic testing para bugs reais de compiladores.

# Agents

- Language/Compiler Test Architect;
- Differential & Fuzzing Engineer;
- Diagnostics/Tooling Test Engineer;
- Memory/UB/Concurrency Verifier;
- ABI/Cross-platform Compatibility Verifier;
- Performance/Benchmark Specialist;
- Independent Correctness Reviewer.

Workforce segue least-workforce: parser change não convoca kernel specialist.

# Evidence

Corpus hash/seed, generator version, reproducer/minimization, target/toolchain, optimization flags, stdout/stderr hashes, sanitizer logs, crash backtrace pointers, semantic mismatch summary e regression link.
