# Visual test layers

1. **Semantic/state assertions** — objeto/material/camera/animation state correto.
2. **Reference render** — screenshot/frame buffer controlado.
3. **Perceptual diff** — tolerances apropriadas a AA, GPU e platform.
4. **Temporal validation** — sequências curtas para efeitos que um frame não captura.
5. **Human review** — mudanças artísticas ou subjetivas.

# Capture contract

Toda baseline deve registrar:

- engine/build;
- platform;
- renderer/API;
- GPU/vendor quando material;
- resolution;
- HDR/color-space;
- quality settings;
- camera transform/FOV;
- scene/seed;
- warmup frames;
- tolerance profile.

# Rendering scenarios

- materials/textures;
- lighting/shadows;
- post-processing;
- transparency;
- particles;
- decals;
- LOD transitions;
- culling;
- z-fighting;
- clipping;
- UI compositing;
- multiple resolutions/aspect ratios;
- platform shader compilation.

# Screenshot caution

Unreal suporta baselines, metadata e tolerances de screenshot, inclusive tratamento de anti-aliasing. O Atlas deve adotar conceito similar: baseline é evidence versionada, não um PNG sem contexto.

Fonte: [https://dev.epicgames.com/documentation/unreal-engine/screenshot-comparison-tool-in-unreal-engine](https://dev.epicgames.com/documentation/unreal-engine/screenshot-comparison-tool-in-unreal-engine)

# Animation verification

Testar:

- state transition legality;
- transition timing;
- blend weights;
- animation notifies/events;
- root motion displacement;
- skeleton/bone mapping;
- retargeting;
- looping;
- interruption;
- movement/collision synchronization;
- network sync quando aplicável.

Root motion merece teste conjunto de animation + movement + collision porque a animação pode dirigir deslocamento físico.

Fonte: [https://dev.epicgames.com/documentation/unreal-engine/root-motion-in-unreal-engine](https://dev.epicgames.com/documentation/unreal-engine/root-motion-in-unreal-engine)

# Audio

Automatizar triggers e budgets:

- event fires once/expected count;
- correct bus/category;
- spatial emitter exists;
- invalid/missing asset detection;
- clipping/peak warnings quando provider permitir;
- voice/concurrency budget;
- synchronization com animation/gameplay event.

Qualidade artística do mix continua humana.

# Interaction testing

Criar scenario matrix para:

- affordance visible;
- range/line-of-sight;
- valid/invalid states;
- hold/tap/double action;
- interruption;
- concurrent interactions;
- inventory/resource prerequisites;
- animation lock;
- save/load while interacting;
- network ownership.

# Game UI/HUD

Reutilizar UI/UX + accessibility skills, mas testar também HUD-specific states: damage, cooldown, ammo, target indicators, world-space markers e resolução/aspect ratio.
