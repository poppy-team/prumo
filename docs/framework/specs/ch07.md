# 07 — Engineering Narrative, Journal, Experimentos e Traceability

> Authority: canonical specification.
> Logical ID: PART1-CH-07
> Source: Notion Living Book (3d59bb7d023f81ad81a3ffdfc455ed5f)
> Status: Especificação de engenharia do Framework (Capítulo 07).


Registrar a evolução significativa do projeto de modo narrativo e técnico, sem armazenar chain-of-thought nem transcrição bruta.

## Unidade recomendada

Um journal por Goal ou milestone material:

```
docs/history/implementation/P01-G01.md
```

## Estrutura de entry

- data/sequence;
- intent;
- contexto técnico relevante;
- o que mudou;
- por que mudou;
- descobertas inesperadas;
- abordagem rejeitada resumida;
- decisões tomadas;
- evidência/testes;
- debt introduzida;
- docs afetadas;
- próximos passos.

## Rejected Approaches Register

Evita que agentes redescubram e repitam soluções já testadas. Deve registrar somente rejeições materialmente úteis, com condições sob as quais poderiam ser reconsideradas.

## Experiment Log

Para hipóteses técnicas:

- hypothesis;
- setup;
- metric;
- result;
- interpretation;
- decision;
- reproducibility pointer.

## Technical Debt Register

Dívida aceita deve ter owner lógico, reason, impact, trigger de revisão e relação com Goal/Task.

## Traceability Graph

Typed edges iniciais:

- `implements`
- `tests`
- `documents`
- `depends_on`
- `supersedes`
- `contradicts`
- `refines`
- `motivated_by`
- `caused_by`
- `fixes`
- `evidenced_by`
- `derived_from`

## Trace query

`atlas trace <capability|goal|file|decision>` deve responder como requisito, design, implementação, testes, docs e evidence se conectam.

## Traceability Matrix

Uma view derivada pode exibir:

```
Capability | Spec | Code | Tests | UX | Evidence | Status
```

## Regra de persistência

Edges e entidades canônicas ficam em JSON/Markdown quando são parte do protocolo. Índice de consulta e backlinks podem viver em SQLite e ser reconstruídos.

## Recomendação adicional — Change provenance

Cada documentation delta material deve registrar de qual Decision/Goal/Task/commit surgiu, permitindo explicar não apenas “o que diz”, mas “por que esta informação existe”.
