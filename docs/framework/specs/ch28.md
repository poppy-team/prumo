# 28 — Kernel, Drivers, Embedded, Fault Injection e Emulação

Criar profile de verificação para software onde falhas podem envolver memória, concorrência, privilege boundaries, hardware state, DMA/MMIO, interrupts e combinações difíceis de reproduzir.

## Test layers

- pure logic/unit no host quando extraível;
- subsystem/integration;
- in-kernel/in-target unit;
- emulator/VM;
- fault injection;
- fuzzing;
- sanitizer/runtime checker;
- hardware-in-loop quando necessário;
- long-running stress/soak;
- cross-architecture/build matrix.

## Linux kernel/driver profile

KUnit para white-box/unit in-kernel; kselftest para userspace/system-level; QEMU/UML quando adequado; kernel fault injection para allocation/I/O/usercopy etc.; KASAN/KCSAN/UBSAN conforme classe; syzkaller para coverage-guided syscall/kernel fuzzing.

## QEMU/device emulation

Usar QTest/provider quando device model e emulação QEMU são parte do alvo. Testar reset/state transitions, invalid register sequences, interrupts, DMA boundaries e migration quando relevante.

## Windows driver profile

Static analysis via CodeQL/WDK guidance, compile warnings/policies e dynamic Driver Verifier em máquinas/VMs de teste. Driver Verifier nunca é rotina casual em máquina de desenvolvimento de uso diário.

## Embedded/firmware

Planejar provider hooks para simulador/emulador, serial logs, board farm/HIL, watchdog/reset tests, power-loss/fault scenarios e resource budgets. Não exigir hardware no core Atlas.

## Skills

`kernel-driver-testing`, `linux-kunit-kselftest`, `syzkaller`, `windows-driver-verification`, `qemu-testing`, `hardware-emulation-testing`, `fault-injection`, `interrupt-concurrency-testing`, `memory-mapped-io-testing`, `embedded-hil`, `resource-budget-testing`, `cross-arch-testing`.

## Specialized agents

Kernel/Driver Verification Engineer, Fault Injection Engineer, Fuzzing Engineer, Hardware/Emulation Test Engineer, Memory/Concurrency Verifier e independent release verifier.

## Safety boundary

Drivers/kernel fuzzing/fault injection devem usar sandbox/VM/test hardware definidos pelo project profile. O Atlas deve bloquear execução destrutiva/privileged em host não autorizado por policy.
