# 49 — Budget Manager, Cost Governance e Rate Limits

> Authority: canonical specification.
> Logical ID: PART1-CH-49
> Source: Notion Living Book (3d59bb7d023f81fc9022f57109b864f8)
> Status: Especificação de engenharia do Framework (Capítulo 49).


## Problema

Token budget isolado não governa um harness real. Recursos limitantes incluem tokens, custo financeiro, chamadas, tempo, concorrência e output de tools.

## Budget Envelope

Scopes hierárquicos: user → workspace → project → Goal → run → agent → step → tool call.

Dimensões:

- input/output/context tokens;
- tool-output tokens;
- LLM calls e tool calls;
- custo monetário;
- wall time;
- concorrência;
- network bytes quando mensurável;
- external-source count.

## Budget reservation

Subagents e providers recebem reservas/fatias, impedindo consumo irrestrito do orçamento pai. Reserva não utilizada retorna ao escopo superior.

## Hard e soft limits

- soft: reduzir agentes opcionais, usar contexto mais enxuto, preferir rota mais barata quando qualidade permitir;
- hard: checkpoint + encerramento seguro, preservando evidence e state.

Nunca permitir que estouro de budget destrua continuidade.

## Cost Manager

Manter pricing metadata separada de model identity e versionada por data. Estimativas devem declarar incerteza.

CLI alvo:

```bash
atlas budget show
atlas budget explain
atlas cost estimate
atlas cost report
```

## Rate Limit Manager

Classificar `429`, quotas e limites de concorrência. Aplicar retry-after, exponential backoff com jitter, fila e circuit breaker. Limites são por provider/model quando necessário.

## Budget evidence

Toda run registra orçamento inicial, reservas, consumo, overage evitado, cache hits quando reportados e razão de qualquer downgrade/stop.

## Policy

Nunca escolher modelo pior para tarefa critical apenas para economizar se isso violar quality policy. Custo é restrição, não autoridade sobre invariants/gates.
