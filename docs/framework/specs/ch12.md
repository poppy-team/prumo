# 12 — Segurança, Trust, Permissions e Supply Chain

> Authority: canonical specification.
> Logical ID: PART1-CH-12
> Source: Notion Living Book (3d59bb7d023f819892a4e3caf2df9141)
> Status: Especificação de engenharia do Framework (Capítulo 12).


O Atlas coordena agentes capazes de ler, editar e executar comandos; portanto configurações de harness, hooks e skills são código/policy potencialmente perigoso.

## Trust layers

- Atlas Core binary;
- canonical project config;
- project-local generated adapters;
- third-party connectors/providers;
- external skills/plugins;
- repository content não confiável;
- model output.

## Regras

- Nunca executar hook project-local novo silenciosamente em projeto não confiável.
- Distinguir generated-by-Atlas de user-owned files.
- Não ler/registrar secrets no Experience Layer.
- Shell actions devem passar por policy quando risk exige.
- Plugins TypeScript não recebem autoridade maior que o core.
- Updates devem ter checksum e idealmente assinatura/verificação de provenance.

## Connector trust

Cada connector deve informar se consegue:

- apenas aconselhar;
- restringir tools;
- bloquear pre-tool;
- verificar post-tool;
- isolar subagents.

## Config merge safety

Nunca substituir integralmente arquivos globais do host. Usar merge estruturado, fragments ou references quando o host suportar.

## Generated artifact markers

Arquivos ou blocos gerados devem incluir metadata machine-readable de ownership/version para permitir atualização e uninstall seguros.

## Supply chain

- pin/version connectors quando aplicável;
- SBOM em releases futuras;
- Dependabot/Renovate ou equivalente;
- govulncheck em CI;
- verificar licenses das dependências;
- preferir standard library quando suficiente.

## Security docs contract

Projetos com capabilities sensíveis devem incluir:

- trust boundaries;
- secrets model;
- auth/authz;
- external integrations;
- data sensitivity;
- destructive actions;
- recovery.

## Recomendação adicional — Safe Mode

`atlas --safe` ou policy equivalente pode desativar shell destrutivo, external plugins e writes fora do root, útil durante adoption de repositórios desconhecidos.

# Amendment 2026-09-21 — Security + Resilience Assurance

[84 — Total Assurance Constitution: Gauntlet Loop, Evidence e Anti-False-Green](../../quality/gauntlet-84.md) e 84.D ampliam o Security Model: threat/security delta deve incluir data integrity, failure containment, parser/input robustness, resource exhaustion, crash/save atomicity, recovery, dependency provenance e adversarial negative-space tests. Security review não encerra em SAST/SCA; high/critical exige evidence do comportamento sob abuso e falha.
