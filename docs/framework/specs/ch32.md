# 32 — Test Provider Contract, Quality Orchestrator e Evidence Normalization

Unificar Playwright, ZAP, CodeQL, fuzzers, compiler suites, sanitizers, UIA/AT-SPI/AX, KUnit, syzkaller e futuros runners sem colocar lógica específica no Atlas Core.

## Test Provider Contract

Todo provider declara `id/version`, host/platform requirements, install strategy, capabilities, inputs/config schema, invocation, output parser, evidence artifacts, isolation requirements, permissions, timeout/resource model, supported risk profiles e cleanup ownership.

## Capabilities exemplares

`test.unit`, `test.integration`, `test.e2e.web`, `test.gui.semantic`, `test.visual`, `test.accessibility`, `test.security.sast`, `test.security.dast`, `test.security.sca`, `test.fuzz`, `test.sanitizer`, `test.differential`, `test.metamorphic`, `test.kernel`, `test.driver`, `test.emulation`, `test.benchmark`.

## Quality Orchestrator

Recebe change impact + risk + project capabilities e resolve mínimo test plan suficiente. Não é agente que inventa resultado: gera plan determinístico/explicável e delega execução a providers/agents.

## Test Plan

Cada plan contém objetivo, risk rationale, providers, suites, environment, required evidence, blockers, optional checks, timeout e expected cost class.

## Evidence Normalization

Schema comum para test run, assertion/finding, artifact pointer, environment/toolchain fingerprint, seed/corpus, retry/flakiness, timing, failure category e provenance.

## Failure taxonomy

Distinguir product failure, test failure, environment failure, flaky/unstable, infrastructure failure, security finding e inconclusive. Não mascarar infrastructure failure como teste aprovado.

## Flakiness policy

Retries não transformam falha em sucesso silencioso. Resultado `flaky` é distinto de `pass`; recorrência gera debt/finding e pode bloquear conforme profile.

## Independent Verification

Risco high/critical pode exigir agente/verificador diferente do implementador e execução limpa da evidência.

## Provider sandbox

Fuzzers, DAST ativo, kernel tools e drivers declaram isolation requirements. Core policy impede executar provider privilegiado fora de environment autorizado.

## Reproducibility

Registrar tool version, config hash, environment fingerprint, seed/corpus ou test selection para reproduzir falhas sempre que possível.

## CLI conceitual

```bash
atlas test plan
atlas test run
atlas test run --profile web-sensitive
atlas test providers
atlas test evidence <run>
atlas test explain
```

## Clean boundary

Skills ensinam estratégia e interpretação. Providers executam ferramentas. Agents planejam/analisam dentro do contrato. Core aplica invariantes, normaliza evidence e decide gates.

# Amendment 2026-09-21 — Assurance Orchestration

[84 — Total Assurance Constitution: Gauntlet Loop, Evidence e Anti-False-Green](../../quality/gauntlet-84.md) amplia o Quality Orchestrator. O resultado normalizado deve distinguir pelo menos pass, fail, flaky, inconclusive, blocked_external, waived e stale. O planner deve consumir Surface/Acceptance Coverage, Evidence Dependency Graph, fault model e risk budgets; hard gates não podem ser compensados por score. Regression selection deve ser impact-aware, mas nunca omitir required evidence silenciosamente.
