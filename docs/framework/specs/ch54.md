# 54 — Execution Environments, Sandbox e Blast-Radius Control

## Princípio

Segurança de harness não é apenas impedir erro; é limitar o impacto quando o erro ocorre.

## Execution Environment Contract

Providers iniciais/futuros: `local`, `git-worktree`, `container`, `vm`, `remote-sandbox`, `hardware-test`.

Campos: filesystem roots, network egress, CPU/RAM/disk/process limits, wall time, environment variables, secrets, device access, privilege level, cleanup e artifact export.

## Seleção por risco

- tarefas normais: local/worktree quando policy permitir;
- repo não confiável: safe/container;
- DAST/fuzzers agressivos: container/VM;
- kernel/driver: VM ou hardware-test autorizado;
- privileged tools: nunca executar casualmente no host.

## Git worktree

Primeiro isolamento barato para agentes paralelos: branch/worktree por task quando necessário, reduzindo conflitos e permitindo rollback simples.

## Network egress

Default-deny ou allowlist em profiles sensíveis. Registrar destinos efetivos quando ambiente permitir.

## Secret injection

Secrets são montados/injetados no menor escopo e duração possíveis; não entram em prompts/logs/evidence.

## Cleanup

Environment deve declarar ownership e cleanup idempotente; falha de cleanup vira finding operacional, não é ignorada.
