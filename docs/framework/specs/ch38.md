# GDD contract

Um GDD moderno deve ser modular, não um monólito congelado. Roles possíveis:

- vision/pillars;
- target player/experience;
- core loop;
- secondary loops;
- mechanics;
- controls;
- progression;
- economy/resources;
- combat;
- AI;
- level/map design;
- narrative;
- UI/UX;
- audio;
- art direction;
- multiplayer/social;
- accessibility;
- monetization somente quando aplicável;
- analytics/telemetry;
- balance model;
- technical constraints;
- scope/non-goals.

# MDA as reasoning tool

O framework Mechanics-Dynamics-Aesthetics deve ser usado como uma das lentes para conectar regras implementadas à dinâmica emergente e à experiência desejada, não como dogma único.

Fonte: [https://aaai.org/papers/ws04-04-001-mda-a-formal-approach-to-game-design-and-game-research/](https://aaai.org/papers/ws04-04-001-mda-a-formal-approach-to-game-design-and-game-research/)

# Balance Model

Modelar explicitamente quando possível:

- damage/time-to-kill;
- resource inflow/outflow;
- upgrade costs;
- progression curve;
- encounter budget;
- reward rate;
- win rate por matchup;
- expected value;
- risk/reward;
- economy sinks/sources;
- dominant strategy indicators.

# Simulation & player models

Usar Monte Carlo/surrogate agents para explorar sistemas, mas registrar o limite do modelo. Trabalhos de survival analysis mostram que skill e learning rate alteram significativamente a curva de dificuldade; portanto balance não deve assumir um jogador estático.

Fonte: [https://ojs.aaai.org/index.php/AIIDE/article/view/12846](https://ojs.aaai.org/index.php/AIIDE/article/view/12846)

# Dynamic Difficulty

DDA deve declarar:

- sinais observados;
- variável de skill estimada;
- ações de adaptação permitidas;
- designer constraints;
- hysteresis/cooldown;
- fairness/transparency policy;
- fail-safe.

Avaliar expressive range das estratégias, não apenas win-rate média. Estudos recentes mostram que explorar gameplay traces pode revelar se directors realmente satisfazem goals de design.

Fonte: [https://ojs.aaai.org/index.php/AIIDE/article/view/36835](https://ojs.aaai.org/index.php/AIIDE/article/view/36835)

# Balance evidence

Mudanças materiais de balance devem produzir:

- rationale;
- baseline;
- simulated result;
- telemetry/playtest evidence quando disponível;
- affected archetypes/matchups;
- rollback conditions.
