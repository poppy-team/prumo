# Por que Playwright

Cobertura Chromium/Firefox/WebKit, BrowserContexts isolados, traces, screenshots/visual comparison, network/console evidence, API testing e integração com axe tornam-no uma base forte para E2E funcional + accessibility + evidence capture.

## Provider ID

`web.playwright`.

## Modos

- project-managed: usa Playwright já instalado no projeto;
- atlas-managed sidecar: futura instalação isolada/cacheada com version pin;
- remote runner: futuro CI/worker.

## CLI conceitual

```bash
atlas test web
atlas test web --journey checkout
atlas test web --security
atlas test web --accessibility
atlas test web --visual
atlas test web --trace on
```

## Atlas Evidence Adapter

Parsear JSON/JUnit/reporters; registrar browser/version, environment fingerprint, route/journey, retries, trace archive, screenshot diffs, console/network errors e attachments.

## Test contracts

Preferir comportamento visível ao usuário e locators semânticos; isolamento por BrowserContext; evitar testes dependentes de internals; fixtures determinísticas; nenhuma dependência entre testes.

## Accessibility

Integração recomendada com `@axe-core/playwright`, sem assumir que automação substitui revisão manual/inclusiva. A11y findings integram schema Atlas.

## Visual regression

`toHaveScreenshot` como camada secundária, com environment fingerprint e tolerâncias explícitas. Não usar pixel-diff como único oracle para comportamento.

## Security usage

Playwright pode gerar authenticated contexts, múltiplos usuários/roles/tenants e journeys que também alimentam ZAP proxy/DAST. Suporta authz replay/tenant boundary harness.

## Política de browser install

Downloads de browsers devem ser explícitos/cacheados e contabilizados no cleanup manifest. `atlas doctor` mostra toolchain disponível e versões.
