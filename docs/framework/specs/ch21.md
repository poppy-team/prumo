# Objetivo

Criar um sistema de Skills suficientemente maduro para ser reutilizado entre harnesses, auditável, testável, progressivamente carregado e capaz de evoluir com evidência sem explodir contexto.

## Atlas Skill Package v3

Estrutura conceitual permitida:

```
skills/<skill-id>/
├── manifest.json
├── SKILL.md
├── CHANGELOG.md
├── knowledge/
├── workflows/
├── templates/
├── checks/
├── scripts/
├── schemas/
├── tests/
│   ├── fixtures/
│   ├── positive/
│   ├── negative/
│   └── evals/
└── examples/
    ├── good/
    └── bad/
```

Nem toda pasta é obrigatória. O manifest declara o que a skill realmente possui.

## Manifest mínimo

Campos: `id`, `version`, `schema_version`, `description`, `maturity`, `activation`, `capabilities`, `requires`, `conflicts`, `permissions`, `knowledge`, `workflows`, `checks`, `scripts`, `tests`, `provenance`, `compatibility`, `context_budget` e `outputs`.

### Activation

Modos: `auto`, `contextual`, `manual`, `required`, `disabled`. A resolução deve considerar intent, capability, risco, project profile e configuração efetiva.

### Permissions

A skill declara necessidades de read/write/shell/network/process/browser etc., mas permissões reais continuam governadas pelo Atlas Core/harness. Skill nunca autoeleva privilégios.

### Outputs

Skills que produzem artefatos estruturados devem possuir output schema.

## Progressive disclosure

Carregar inicialmente somente manifest + resumo do `SKILL.md`. Workflows e knowledge são carregados sob demanda. `context_budget` limita quanto uma skill pode contribuir para o LPC.

## Lifecycle

`draft → experimental → recommended → verified → deprecated → retired`.

Promoções exigem review/evals adequados. Deprecation possui replacement e migration note quando houver.

## Skill Evals

Cada skill relevante deve demonstrar ganho em tarefas-alvo comparando baseline vs skill. Métricas podem incluir correção, cobertura, violações, precisão de ativação, tokens, latência, falso positivo, falso negativo e adherence ao output contract.

## Configuração em camadas

```
built-in defaults
→ user profile
→ workspace
→ project
→ recipe
→ session
```

Precedência efetiva: session > recipe > project > workspace > user > default, exceto `required` de escopo superior que não pode ser desligado em escopo inferior sem política explícita.

## CLI proposta

```bash
atlas skill list
atlas skill inspect <id>
atlas skill enable <id> --global|--workspace|--project|--session
atlas skill disable <id> ...
atlas skill status
atlas skill eval <id>
atlas skill verify <id>
atlas skills curate
atlas skill migrate <id>
```

## Ambient Skill Resolver

Sempre executa somente sobre metadata. Resolve a menor composição útil de skills e só depois carrega conteúdo. Nunca carregar toda skill marcada `auto` em cada turno.

## Skill Bundles

Bundles são conjuntos candidatos, não execução obrigatória. Ex.: `go-service`, `desktop-gui`, `compiler`, `saas-web`. O resolver ainda reduz ao mínimo necessário.

## Skill Curator

Detecta overlap, duplicação, conflito, stale references, knowledge excessivo, baixa utilização, weak evals, triggers ruins, skills que deveriam fundir/dividir e dependências circulares.

## Experience → Skill Proposal

Experience Pass pode propor criação/extensão de skill com evidências de Goals/sessões. Mudanças não são promovidas silenciosamente.

## Métricas de maturidade

Quantidade de skills deixa de ser KPI. KPIs: cobertura útil, precisão de ativação, evals, baixa redundância, freshness, incidentes evitados, custo de contexto e estabilidade.
