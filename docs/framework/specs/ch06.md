# 06 — Adoption Engine para Projetos Existentes

> Authority: canonical specification.
> Logical ID: PART1-CH-06
> Source: Notion Living Book (3d59bb7d023f81d08858d501ae093847)
> Status: Especificação de engenharia do Framework (Capítulo 06).


Permitir que projetos existentes sejam incorporados ao Atlas sem reorganização destrutiva e sem reescrever documentação apenas para satisfazer nomes de pasta.

## Comando principal

`atlas adopt [path]`

## Pipeline

1. Detectar root/repository.
2. Inventariar linguagens, build systems, packages, CI, tests, configs e deployment.
3. Classificar capabilities.
4. Descobrir documentação atual.
5. Mapear documentos existentes para semantic roles Atlas.
6. Detectar duplicações, lacunas, divergências e conteúdo possivelmente stale.
7. Inferir arquitetura apenas quando evidência é suficiente.
8. Gerar Adoption Report.
9. Iniciar entrevista somente para ambiguidades relevantes.
10. Propor migration patches incrementais.

## Fontes de evidência

- README e docs;
- manifests/build files;
- source tree;
- tests;
- CI;
- configs;
- schemas;
- Git history;
- ADRs/changelogs;
- agent instructions existentes;
- comments estruturais de módulos.

## Semantic mapping

Exemplo:

```
SYSTEM_DESIGN.md -> architecture.overview
CONTRIBUTING.md#Tests -> testing.contributor-workflow
ui.md -> ui.overview (partial)
```

O arquivo pode permanecer no lugar original. O Atlas registra a função semântica.

## Regras de não destruição

- Não mover docs automaticamente sem benefício explícito.
- Não apagar docs contraditórias; primeiro classificar e propor resolução.
- Não transformar inferência em decisão humana.
- Preservar Git history e links externos sempre que possível.

## Adoption Report

Deve listar:

- capabilities detectadas;
- documentation profiles aplicáveis;
- cobertura atual;
- blockers;
- duplicate knowledge;
- contradictions;
- stale candidates;
- missing contracts;
- migration phases.

## Modes

- `--audit-only`: nenhuma modificação.
- `--interactive`: entrevista e patches guiados.
- `--non-interactive`: apenas mudanças seguras de scaffolding/mapping.
- `--strict`: exige readiness mínimo antes de ativar execution mode.

## Recomendação adicional — Confidence ledger

Toda inferência do adoption scanner recebe confidence + evidence pointers. Informações abaixo de um limiar não entram como canônicas; viram pergunta.
