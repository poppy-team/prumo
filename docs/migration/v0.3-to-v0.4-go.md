# Migration Guide: Prumo v0.3 (Python) to v0.4 (Go)

## 1. Executive Summary & Objective

This document defines the baseline and incremental migration roadmap from Prumo v0.3 (written in Python) to Prumo v0.4, whose Core and CLI are implemented in Go.

During the migration, the Python implementation (`src/prumo/`) acts as the executable specification and conformance oracle. No existing Python runtime code, tests, schemas, or examples are modified or removed until Go achieves verified parity.

## 2. Current v0.3 Baseline

### Runtime & Entrypoints
- **Python version**: Python 3.10+ (tested on 3.10, 3.11, 3.12, 3.14).
- **CLI Entrypoint**: `prumo.cli:main` (`pyproject.toml` script `prumo = "prumo.cli:main"`).
- **CLI Subcommands**: `init`, `resolve`, `validate`, `goal`, `context`, `report`, `migrate`, `compile`, `snapshot`, `doctor`, `explain`, `framework-check`.

### Canonical Contracts
- 27 JSON Schemas in `schemas/`.
- Workforce catalog in `src/prumo/resources/catalog/`.
- Adapter templates in `src/prumo/resources/adapters/`.
- Workforce packages in `src/prumo/resources/workforce/`.
- Fixtures in `conformance/` and tests in `tests/`.

### Baseline Tests
- `pytest`: 127 tests passing.
- Coverage: 81% on Python v0.3.
- `conformance/V03_BASELINE.json`: baseline manifest.
- `conformance/M0_CONFORMANCE_MATRIX.json`: cataloged Python oracle cases.

Python v0.3 remains in the repository and remains the oracle. No Python runtime files, schemas, or existing fixtures were deleted or moved.

## 5. Current Implementation Detail

The Go validator now implements JSON Schema Draft 2020-12 semantics in pure Go (`internal/validation`): `type`, `required`, `properties`, `additionalProperties`, `items`, `enum`, `const`, `pattern`, `minLength`, `minimum`, `allOf`, `anyOf`, `oneOf`, and local `$ref` resolution by filename and `$id`. `conformance/golden/m3/compiler-parity.json` records byte-identical compiler output for all seven targets.

The Go doctor now includes version/protocol checks, Goal locks and dependencies, Plan/goal references and DAG errors, workforce manifests, skill provenance, model roles/profiles, execution backends, invalid gates, and missing evidence.

`framework-check` now matches Python v0.3 for duplicate catalog IDs, agent/recipe skill references, skill dependencies, bundle references, workforce package manifests/documents/schema validation, adapters, and required schemas.

The Go migration handles v1 YAML profiles and goal files through a minimal legacy-only YAML reader, then v2 JSON through v3 protocol upgrade.

Single-binary assets are available at the module root through Go `embed` (`schemas`, adapters, catalog, and workforce). Ownership metadata is written separately beside compiled runtime targets.

M4 foundation now includes `internal/install`, portable `PRUMO_HOME`/`--home`, idempotent `setup`, connector install state, safe uninstall/purge behavior, release cross-build script, checksums, and GitHub release workflow. Connector-specific cleanup manifests are consumed when present; missing ownership is reported rather than guessed.

Known intentional semantic boundary: generated JSON files are compared by parsed value, not byte order, because Go map serialization orders keys differently from Python insertion order.

## 6. Criteria for Python Runtime Removal

Python v0.3 retirement criteria status:
1. [x] Full Draft 2020-12 schema validation parity is verified (`internal/validation`).
2. [x] All critical CLI, protocol, filesystem, migration, and compiler contracts pass differential conformance (`conformance/golden`, `internal/cliops`).
3. [x] All explain/runtime surfaces required by the release are implemented (`internal/cliops`, `internal/runtime`).
4. [x] Go binaries are available on target platforms (`scripts/build-release.sh`, GitHub Actions).
5. [x] Installation documentation no longer requires Python.
6. [x] Milestones M0 through M12 and Adoption Engine F-G01 through F-G06 completed with 100% test passing.
7. [x] Legacy scripts, Python test suite (`tests/`), modules (`src/prumo/*.py`), and packaging (`pyproject.toml`) retired via ADR 002.

## 7. Python Runtime Retirement Completed

As formalized in ADR 002 (`docs/adr/002-retire-python-runtime.md`), all legacy Python runtime code, test files, and package configurations have been removed from the repository.

Prumo v0.4 is a 100% pure Go distribution with zero Python runtime dependencies. Canonical resources (`src/prumo/resources/`, `schemas/`, `adapters/`) are preserved as embedded JSON/Markdown assets via `embedded_assets.go`.
