# Structured Design Critique & Review Guide

## 1. Critique vs. Review
- **Critique:** A collaborative process occurring *during* the design phase aimed at improving the craft. It focuses on exploration, identifying blind spots, and ideation.
- **Review:** A milestone checkpoint designed for stakeholder approval. It evaluates whether the design meets predefined requirements and business goals.

## 2. The Feedback Protocol
Effective feedback is objective, empathetic, and actionable. Avoid prescriptive commands.
Use the following framing:
- **"I notice..."** - States an objective observation without judgment. (e.g., "I notice the primary CTA is the same color as the secondary buttons.")
- **"I wonder..."** - Raises a question about the impact of the observation. (e.g., "I wonder if users might miss the primary action.")
- **"What if..."** - Offers a non-prescriptive suggestion for improvement. (e.g., "What if we increased the contrast or used our primary brand color for that CTA?")

## 3. Severity Rating Scale
To help prioritize feedback, use this severity scale:
1. **Cosmetic:** Visual polish issues; does not impede usability.
2. **Minor Usability:** Causes slight friction; users can easily recover.
3. **Major Usability:** Significant friction; impedes task completion for some users.
4. **Catastrophe:** Critical blocker; prevents users from completing primary goals.

## 4. Evaluation Criteria
- **Usability:** Are interactions predictable? Is the cognitive load minimized?
- **Strategic Alignment:** Does the design solve the business problem?
- **Brand Consistency:** Are components and tokens used correctly?
- **Visual Quality:** Is there clear visual hierarchy? Is spacing consistent?
- **Accessibility:** Does it meet WCAG 2.1 AA standards? Evaluate contrast ratios ($CR \ge 4.5:1$ for normal text), keyboard navigation, and aria labels.
- **Technical Feasibility:** Can engineering implement this efficiently?
- **Content Clarity:** Is the copy concise and jargon-free?
